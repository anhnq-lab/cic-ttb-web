# Audit Report - 2026-01-20

## Summary
- 🔴 Critical Issues: 1
- 🟡 Warnings: 4
- 🟢 Suggestions: 3

## 🔴 Critical Issues (Phải sửa ngay)
1. **Thiếu Input Validation (Backend)**
   - **File:** `server/index.js`
   - **Nguy hiểm:** API nhận dữ liệu trực tiếp từ `req.body` mà không kiểm tra (VD: `title`, `content` trong News API). Hacker có thể gửi dữ liệu rác, script độc hại (XSS) hoặc làm crash server.
   - **Cách sửa:** Sử dụng thư viện validate như `zod` hoặc `express-validator` để kiểm tra dữ liệu đầu vào.

## 🟡 Warnings (Nên sửa)
1. **Cấu trúc Monolithic trong `server/index.js`**
   - **File:** `server/index.js`
   - **Mô tả:** File này quá dài (400+ dòng) và chứa cả logic định nghĩa Route lẫn Controller cho News, Library, Contact, Pricing...
   - **Tác động:** Khó bảo trì, khó test và dễ gây lỗi khi code chung team.
   - **Cách sửa:** Tách logic ra các file Controller riêng (VD: `controllers/newsController.js`) và Route riêng.

2. **Inconsistent Routing Pattern**
   - **File:** `server/index.js`
   - **Mô tả:** Một số modules (`auth`, `projects`, `ai`) đã được tách ra file route riêng, nhưng `news`, `library`, `tools`... lại viết thẳng trong `index.js`.
   - **Cách sửa:** Chuẩn hóa toàn bộ về pattern Router riêng biệt.

3. **Thiếu Error Handling tập trung**
   - **File:** `server/index.js`
   - **Mô tả:** Code sử dụng `try-catch` rải rác hoặc trả về 500 thủ công. Không có middleware xử lý lỗi centralized.
   - **Cách sửa:** Viết `errorMiddleware` để bắt lỗi toàn cục và log lỗi chuẩn xác.

4. **Package Management chồng chéo**
   - **Mô tả:** Có 2 file `package.json` (root và `server/`). Việc cài đặt dependencies có thể gây nhầm lẫn nếu không rõ ràng context.
   - **Cách sửa:** Cân nhắc dùng yarn workspace hoặc giữ nguyên nhưng document rõ ràng quy trình build/deploy.

## 🟢 Suggestions (Tùy chọn)
1. **Tối ưu SEO Images**
   - Backend hiện tại nhận base64 image (giới hạn 10MB). Nên cân nhắc upload lên Storage (như Supabase Storage) và chỉ lưu URL để giảm tải database và tăng tốc độ API.

2. **Rate Limiting**
   - Chưa thấy cơ chế chống spam request API. Nên thêm `express-rate-limit`.

3. **Logging**
   - Hiện tại chỉ dùng `console.log`. Nên dùng `winston` hoặc `morgan` để log request/error chuyên nghiệp hơn.
